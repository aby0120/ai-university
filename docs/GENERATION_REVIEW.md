# 离线教材生成与复核流程

这是一套 **AI 制作 → 固定内容 → 静态发布** 的流程，不要求网站调用模型。本地也不需要 API。可在任意 AI 编辑环境中完成书稿生成，再将已生成内容存入仓库。

1. **先完成课程边界。** 列出整卷章节、学习目标、先修边与读者起点。明确后续卷范围，但不以未写正文的目录占位冒充完成。
2. **逐章编写。** 输出符合 schema 的 JSON；每节有解释、条件、推导、两例题和四道完整解答。章节例子服务于概念，而非拼接相互无关的题目。
3. **AI 数学复核。** 使用独立复算思路：代回、求导、单侧检查、单位检查、定义域反例与另一种解法。要求指出错误或条件缺失，不能仅回复“看起来正确”。此步骤可在同一编辑环境中进行，不需要集成运行时服务。
4. **程序检查。** `npm run validate:content` 校验结构、所有公式渲染、目录、来源、误区标签、先修 DAG 与节顺序。`npm test` 对可视化模型做独立有限差分、解析积分或几何比较。
5. **浏览器检查。** 逐节确认正文与演示能打开，极端滑块值不会产生无效图元，定义域限制可理解。检查键盘、手机目录、练习提示、数值检查、记录保存及整本阅读链接。
6. **整卷完成再发布。** `npm run build` 从相同 canonical 内容生成网站、完整 Markdown 与打印 HTML；更新版本、QA 和 CHANGELOG，然后发布同一个提交。

## AI 复核提示模板

```text
请作为数学复核者检查这份 learning object。
不要只评文风。逐一检查：
定义域与定理前提；推导每一步是否合法；极限与单侧情况；
每道例题与练习的答案；单位、符号与近似误差；图示模型与正文是否一致。
尽量使用独立解法复算，并给出具体反例。
输出：确定错误、需要补充的条件、复算证据、尚未验证的部分。
不要声称有人类审校，也不要只因图像采样吻合就宣称证明成立。
```

## 版本透明度

这套流程允许纯 AI 完成教材，并不设置“必须先由人类批准”的制作门槛。与此同时，不能把自动检查写成“整本数学已证明正确”。首版记录 `author=AI-generated`、`humanReviewed=false`，发现错误即通过勘误和版本修订。人工贡献可增加质量，但不是运行或制作教材的前提。
