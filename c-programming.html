SECTION 1.1

从文件到可运行的程序

C 程序让计算机按明确的步骤处理数据；第一件事是走通“编辑、编译、运行”的完整流程。

怎么理解？

源文件像写好的菜谱，可执行文件像能够按菜谱工作的机器。修改菜谱不会自动改好机器；保存后还必须重新编译。编辑器负责写字，编译器负责翻译，终端负责接收命令，它们各有工作。

学习目标

  • 准备练习目录
  • 安装一个 C 编译器
  • 保存真正的文本文件
  • 第一次编译和运行

准备练习目录

本书不要求你会终端。终端是输入命令并看到文字结果的窗口。先在用户目录创建 c-study 文件夹，避免目录名中的空格干扰首次练习。打开终端，输入 mkdir c-study 回车，再输入 cd c-study 回车。mkdir 创建目录；cd 改变当前目录。若目录已存在，只执行 cd。用 pwd 查看位置，用 ls 查看文件；Windows 本书统一使用 MSYS2 UCRT64 终端，那里也支持这些命令。

安装一个 C 编译器

Windows 64 位 x86 电脑：从 MSYS2 官网安装，打开名为 UCRT64 的终端，运行 pacman -Syu；若提示关闭终端，照提示关闭后重开 UCRT64，再更新，随后运行 pacman -S --needed mingw-w64-ucrt-x86_64-gcc。ARM64 电脑请按官网对应环境安装，不照抄 x86 包名。macOS：打开“终端”，输入 xcode-select --install 并完成系统安装窗口。Ubuntu/Debian：在终端运行 sudo apt update，再运行 sudo apt install build-essential。安装需要网络；日常练习不需要网络。

SECTION 1.2

读懂第一段代码与输出

认识程序的标点和输出方式，就能把一段“能运行的代码”读成有顺序的动作。

怎么理解？

从 main 的左花括号进入，一句一句向下执行。分号像一句话的句号，花括号把多句组成一个整体；缩进让人看清层级，但在这里不决定执行顺序。

学习目标

  • 逐个读符号
  • 换行和转义
  • printf 是带空位的模板

逐个读符号

#include <stdio.h> 让本文件获得标准输入输出函数的声明。int 是 main 返回值的类型；void 表示这个写法不接收参数。函数名后写括号，函数体用花括号包住。puts("Hi"); 是一次函数调用：把文字交给 puts。字符串用英文双引号，分号在括号外。

换行和转义

puts 会在字符串末尾增加一个换行；printf 不自动增加。反斜杠加 n 写作 \n，表示一个换行字符，不是打印两个字母。\t 表示制表符，\" 表示字符串内的双引号，\\ 表示反斜杠。屏幕上的列宽、制表符位置可能因终端而不同，本书不靠它们对齐表格。

printf 是带空位的模板

printf 的第一个参数是格式字符串。%d 是整数空位，后面的整数按顺序填进去；%% 才是打印百分号。先数清空位，再数后面的参数。不要把读者输入当成格式字符串。注释 // 直到行尾，或 /* 到 */，用于解释意图，不参与运行；块注释不能互相嵌套。

定义与条件

语句按控制流执行；字符串是双引号包围的字符序列。printf 的格式说明必须与传入参数的实际类型匹配。

  • 调用函数前包含声明它的头文件。
  • 本节 %d 对应 int；文字直接写在格式字符串内。
  • 屏幕显示与标准输出不同：你在键盘输入的回显不算程序输出。

过程解释

  1. 从 main 开始，先找每个分号结束的语句。
  2. 把字符串里的转义字符解释成实际字符。
  3. 按执行顺序拼接输出，并只在明确换行的位置换行。

概念检查

printf("%d%%", 8) 写出什么？

  • A. 8%%
  • B. 8%
  • C. %d%

答案：B

  • A：%% 在格式里表示一个百分号。
  • B：正确，%d 用 8 填入，%% 输出一个 %。
  • C：%d 会按参数替换，不保留原样。

SECTION 1.3

变量、类型与初始化

变量把会变化的数据命名，类型规定这些数据能表示什么、怎样参与运算。

怎么理解？

把变量想成有标签的储物格：标签是名字，格子的规格是类型，里面的东西是值。这个比喻只帮助理解；实际类型范围要查标准头文件，不能凭“格子看起来大”猜测。

学习目标

  • 声明时就给初值
  • 先学四类常用类型
  • 格式与只读意图

声明时就给初值

int count = 3; 创建一个 int 对象并把初值设为 3。后续 count = 5; 是赋值，不是数学等式；它把右侧结果存到左侧对象。名字区分大小写。用含义明确的英文名如 item_count，比 a、b、c 更容易排错。局部自动变量若没有初始化，不能把读到的内容当作可用数字。

先学四类常用类型

int 保存常用整数；double 保存有小数的近似数；char 保存一个字符编码单位；size_t 表示 sizeof 得到的大小和容器长度。char 的位数不保证恰好为 8，int 也不保证为 32 位。sizeof 的单位是 C 的字节，sizeof(char) 必为 1。本书不把机器上的某次大小当作语言保证。

格式与只读意图

printf 输出 int 用 %d，double 常用 %.2f 显示小数点后两位，char 用 %c，size_t 用 %zu。const int days = 7; 表达之后不通过这个名字改值的意图。const 不是任意上下文里的编译期常量，也不让所有相关存储自动不可变。金额优先使用整数分，避免把二进制近似小数当作精确货币。

定义与条件

对象是保存值的存储区域；变量名标识对象。初始化为新对象提供初始值，赋值更新已有可修改对象的值。

  • 先初始化，再读取。
  • 格式符与参数类型匹配。
  • 不假定 int、指针或 double 的固定字节数；范围查 limits.h。

过程解释

  1. 根据数据含义选择类型。
  2. 声明时给初始值，计算时先读右侧再写左侧。
  3. 按类型选择输出格式，观察打印精度与内部值的区别。

概念检查

哪句保证第一次读 count 前已有确定初值？

  • A. int count;
  • B. int count = 0;
  • C. printf("%d", count);

答案：B

  • A：声明没有为这个局部自动对象提供初值。
  • B：正确，初始化为零后可以读取。
  • C：输出语句不能替变量补初值。

SECTION 1.4

运算、转换与数值边界

表达式把数据变成结果；理解运算发生在哪种类型里，才能避免“看起来算对、结果却错”。

怎么理解？

先决定用整数尺还是小数尺，再计算。把整数除法的结果放进 double，不会让先前丢掉的小数重新出现。

学习目标

  • 整数商和余数
  • 转换发生的时间
  • 优先级和副作用
  • 范围是程序条件

整数商和余数

两个整数相除得到整数商，C17 向零截断：7 / 2 是 3，-7 / 2 是 -3。% 只用于整数，-7 % 2 是 -1；被除数等于商乘除数再加余数。除数必须非零，且商可表示；例如最小有符号整数除以 -1 也可能越界，不能只检查零。

转换发生的时间

double a = 7 / 2; 先执行整数除法，a 才得到 3.0。写 7.0 / 2 或 (double)7 / 2 才先进入浮点运算。强制转换写在表达式前的圆括号里。转换不自动验证范围；浮点数转整数会向零截断，但超出目标整数可表示范围不能依赖。

优先级和副作用

乘除取余先于加减；不确定就加括号。++ 是更新变量的操作，初学时单独写一行，例如 i++;。不要写 i++ + i++ 这样的未定序多次修改，也不要假设函数各实参从左向右求值。把复杂表达式拆成几句能直接减少这类问题。

范围是程序条件

有符号整数溢出属于未定义行为，不保证绕回。unsigned 按模运算回绕，但仍可能破坏业务结果。混用有符号和无符号数会触发转换，例如负数可能变成很大的无符号数。先用本书限定的小范围数据，后面再学 limits.h 和操作前检查。浮点数是近似表示，显示两位只是输出格式，不是改变内部精度。

定义与条件

表达式依据操作数类型执行转换和运算；赋值目标的类型通常在右侧求值后才起作用。

  • 所有运算结果在相应类型的合法范围内。
  • 整数除法的除数非零，且商可表示。
  • 不依赖未定序副作用或精确的浮点十进制表示。

过程解释

  1. 先标记每个操作数的类型。
  2. 按括号和优先级计算中间结果，并检查范围。
  3. 最后赋值或输出，确认转换发生在运算之前还是之后。

  • B：正确，整数商 2 再转换成 2.0。

SECTION 2.1

条件判断与逻辑

条件语句让程序根据数据选择行动，避免所有输入都执行同一段处理。

怎么理解？

像检票：先判断“是否有票”，再决定放行或提示。条件是一个可求值的表达式，不是自然语言里省略条件的句子。

学习目标

  • 比较与分支
  • 多个条件一起检查
  • 顺序决定分类

比较与分支

if (score >= 60) 后写花括号包围的动作，else 写条件为假时的动作。== 比较是否相等，= 赋值。C 把零当假、非零当真；比较运算结果是 int 类型的 0 或 1。即使只有一条语句也保留花括号，减少后来加代码时的错误。

多个条件一起检查

&& 表示两者都满足，|| 表示至少一个满足，! 取反。写范围检查 age >= 0 && age <= 150，而不是 0 <= age <= 150；后者先算左边得到 0 或 1，再与 150 比较。&& 和 || 从左向右短路，左侧已能决定真假时不计算右侧。

顺序决定分类

else if 形成互斥分类，按顺序找到第一个真分支就停止。分数等级从高阈值往低阈值写，否则较高分可能先被“>=60”截住。先验证输入是否合法，再做业务分类，让非法值不会意外被当作优等。

定义与条件

if 根据控制表达式与零是否相等选择分支；&&、|| 有从左到右的短路规则。

  • 比较两侧类型和数值范围明确。
  • 除法前用短路排除零除数，并排除不可表示的商。
  • 本书分支均使用花括号。

过程解释

  1. 先列合法范围，再列互斥的业务情况。
  2. 把每一条自然语言条件写成完整比较，用 && 或 || 连接。

SECTION 2.2

让程序接收键盘输入

输入让同一个程序处理不同数据；读取是否成功必须成为程序流程的一部分。

怎么理解？

读取像填写表格：想要一个整数，不代表读者一定交来整数。先检查这一格是否填成功，再使用数据。

学习目标

  • 先理解标准输入
  • 返回值是第一道检查
  • 本节方法的边界

先理解标准输入

程序的标准输入通常连接键盘。在终端运行后，光标停着可能是在等待输入。键入 12 后按回车，文本才交给程序。scanf("%d", &age) 尝试把文本转成 int；&age 是让函数把结果放到 age 的位置，& 的细节在指针章展开，本节先识别它的职责。

返回值是第一道检查

scanf 返回成功赋值的项目个数。读取一个 int 时检查是否等于 1；两个 int 检查是否等于 2。读取失败就输出错误并结束，不继续使用结果。%d 跳过前面的空白，但读取完成后可能留下换行。不要在本书的格式末尾写空白或 \n，以免交互时继续等待下一段非空白。

本节方法的边界

scanf 的整数转换不适合处理任意不可信文本：数值超出目标对象可表示范围时，C 的标准接口没有给你一个可靠的范围错误返回。课堂练习假定输入整数在 int 范围内，再检查业务范围。后面将用 fgets 读整行、strtol 检查完整格式与范围。本节不把 scanf 当作最终的健壮输入方案。

定义与条件

scanf 从标准输入按格式转换，返回成功赋值的项目数，或在首次转换前输入失败时返回 EOF。

  • 输入数值可由目标类型表示；不满足时改用后文的 fgets + strtol。
  • %d 的目标为 int 对象地址。
  • 业务范围检查在读取成功后进行；不要用失败后的值。

过程解释

  1. 创建并初始化输入变量。
  2. 调用 scanf，先判断返回值是否等于预期个数。

SECTION 2.3

switch：多选分支与菜单雏形

switch 把同一个整数值的多种情况集中写在一起，适合固定编号的菜单。

怎么理解？

把输入编号看成柜台号码；case 是柜台标志，break 让本次办理结束。case 本身只是标签，不会自动停止后续执行。

学习目标

  • 从编号选择动作
  • 理解落入后续分支
  • 为意外输入留路径

从编号选择动作

switch (choice) 先计算一个整数类型的控制值，匹配某个 case 的整数常量表达式；未匹配时选择 default。case 后是冒号，不是分号。case 值不能重复，不能用运行时变量当作任意标签。字符串和范围条件用 if 或其他结构处理。

理解落入后续分支

执行到 break 才退出当前 switch；如果省略，会继续向下执行，称为贯穿。多个 case 共用一段处理时可以有意相邻放置，但必须写注释解释。continue 针对循环，不是 switch 的“下一项”按钮。

为意外输入留路径

菜单编号不在已知集合时，default 提示 unknown option。分支内若声明临时局部变量，可用一对额外花括号建立块作用域，避免标签和声明带来的可读性问题。复杂处理以后抽成函数，switch 只负责选择，不把整个项目塞进一个大分支。

SECTION 2.4

while、哨兵与终止条件

循环让程序重复执行动作；正确的终止条件保证工作会做完，也保证不多做一次。

怎么理解？

每次绕圈前先看门口的条件。若从一开始就不满足，while 的身体一次都不执行。

学习目标

  • 三个部分一起设计
  • 哨兵不属于数据
  • 累计值和空输入

三个部分一起设计

写循环前列出初始状态、继续条件、状态更新。int n = 3; while (n > 0) { ...; n--; } 每轮减少 n，最后到零退出。若忘记更新，条件可能永久为真。不要先写 while(1) 再祈祷某处会结束；确需无条件循环时，明确每一条 break 或 return 路径。

哨兵不属于数据

读取多个分数可约定 -1 表示结束，称为哨兵。先检查是否为 -1，再参与求和与计数；不要把哨兵也加进去。读取失败也应退出或有明确恢复方案，不能每次对同一个无法转换的字符重试。EOF 表示输入结束，不是正常数值；终端如何发送 EOF 因环境而异，也可用输入重定向练习。

累计值和空输入

sum 从 0 开始，count 从 0 开始；每次接受一条合法数据再更新它们。求平均值前先检查 count > 0。空数据集不是平均值为零，而是平均值尚未定义。总和仍须检查范围；本节固定用小数据，完整项目会以记录上限保证总和可表示。

定义与条件

while 在每轮之前判断条件，条件为非零时执行循环体，再回到条件；break 立即离开最近循环。

  • 循环状态必须有能解释的进展。
  • 累计运算在合法范围内。
  • 数据结束、格式失败和业务非法值各有明确路径。

过程解释

  1. 写下初值和每轮结束后的状态。

for 循环与嵌套循环

怎么理解？

用一张小表写出每轮的 i，比凭感觉数循环次数可靠。嵌套循环则像表格：外层选行，内层逐列处理。

学习目标

  • 读懂 for 的四个阶段
  • 次数与下标分开
  • 嵌套的工作量

读懂 for 的四个阶段

for (int i = 0; i < 3; i++) 先初始化一次，然后依次判断、执行循环体、更新，再回到判断。i 取 0、1、2，一共三次。continue 会转到 for 的更新部分，再判断；break 则完全离开。不要在 for 后误加分号，否则循环体变成空语句。

次数与下标分开

从 0 开始不是 C 的强制风格，而是与数组下标相配。处理 n 个元素通常使用 i < n；i <= n 会多访问一个。用 size_t 表示长度时，避免写 i >= 0 的无符号倒序循环；无符号数永远不小于零。可以从 n 开始，在 i > 0 时访问 i - 1。

嵌套的工作量

外层循环每走一轮，内层会完整执行一次。两行三列总共六次内层动作。生成矩形时，内层输出每列，内层结束后再输出换行。若内层做 n 次、外层也做 n 次，动作数量按平方增长；这为后面的算法复杂度建立直觉，不代替性能测量。

定义与条件

for 由初始化、控制条件、更新表达式和循环体组成；内层变量可以在各自块中独立生存。

  • 循环计数与结果可表示。
  • 访问长度为 n 的数组时只用 0 到 n-1 的下标。
  • 无符号循环不依赖“小于零”。

过程解释

  1. 把初始化写在第一次判断之前。
  2. 逐轮列出条件成立时的变量值。
  3. 嵌套时固定一个外层值，完整追踪内层，再换下一个外层值。

函数：拆出能重复使用的动作

函数把一项任务命名，让同一计算可以重复调用，也更容易单独检查。

怎么理解？

函数像有输入格和输出格的小机器：参数给输入，return 交结果。调用一次，就建立一次新的局部执行过程。

先写输入输出契约

例如 int square(int value) 接收一个 int，返回它的平方。函数定义包含返回类型、名字、形参列表和函数体。先明确合法输入范围：若乘积不能用 int 表示，函数就不该直接相乘。本节限定参数在 -100 到 100，乘积在 int 的标准最小保证范围内。

调用传的是值

square(n) 会把 n 的值交给形参 value。修改 value 不会改调用者的 n，这叫按值传递。想改调用者对象，后面通过指针传递地址；指针本身也仍是按值传递。没有参数的函数写 (void)，在本书 C17 基线下不能把空括号声明当作同样明确的参数契约。

声明与返回

调用处之前必须看得见函数声明。小程序可把定义放在 main 前，项目可在头文件放原型。非 void 函数在每个需要返回的路径上提供合适值；不要指望走到底自动获得正确结果。void 函数不返回业务值，可用 return; 提前结束。计算函数尽量不夹杂 scanf 与 printf，输入输出留在外层。

定义与条件

函数封装可调用的语句序列；实参的值初始化形参，return 将控制交还调用者并可提供一个结果。

  • 调用前有匹配的声明。
  • 实参符合约定范围。
  • 不依赖实参求值顺序，不返回局部对象地址。

  1. 用一句话规定函数做什么以及合法输入。

作用域、生命周期与程序状态

怎么理解？

作用域像地图上能看到标签的区域，生命周期像储物柜实际租用的时间。看不见标签，不等于柜子一定销毁；看得见指针，也不等于它指向的对象仍存在。

学习目标

  • 块作用域
  • 自动与静态存储期
  • 全局状态谨慎使用

块作用域

花括号建立块。块内声明的普通局部变量，通常只有从声明处到块末尾可用。内层可声明同名变量遮蔽外层，但容易读错，本书尽量用不同名字。for 初始化中声明的 i 通常只在该 for 的范围内可见。

自动与静态存储期

普通局部对象每次进入对应块时有新的实例，离开块时生命周期结束。static 局部对象则在整个程序运行期间存在，只初始化一次，名字仍局限于函数内部。它能保留状态，但隐藏状态会使测试互相影响。初学主线优先显式通过参数与返回值传状态。

全局状态谨慎使用

文件作用域的对象可在函数外声明。过多全局可变状态让你难以判断哪个函数改变数据，也难以重复测试。用 const 表达固定配置，用函数参数表达输入，用返回值或明确的输出参数表达结果。生命周期错误在指针章会再次出现，此时先记住“离开块后，普通局部对象不存在了”。

定义与条件

作用域决定标识符的可见范围；存储期与生命周期决定对象存在的时段。它们不是同一个概念。

  • 不读取已结束生命周期的对象。
  • static 局部状态跨调用保留，不能当作每次重置。
  • 演示静态变量仅说明机制，不鼓励隐藏业务状态。

过程解释

  1. 先圈出每个声明所在的块。
  2. 逐次调用时区分新建的局部对象和保留的静态对象。
  3. 检查函数输出是否依赖之前的调用，决定是否应改成显式状态。

  • B. 不会，只初始化一次

答案：B

  • A：普通自动局部变量通常每次建立新实例。

SECTION 3.4

读诊断、手工追踪与最小测试

排错先把“哪里不符合预期”缩小成可复现事实，再修改最小的一处。

怎么理解？

编译器诊断像路线指示牌：它告诉你在某处无法继续理解，不保证那一行就是根因。漏掉前一行分号，也可能让下一行报错。

学习目标

  • 三种问题分开处理
  • 做一个最小复现
  • 用断言保留发现

三种问题分开处理

编译错误说明不能生成有效程序，例如缺分号、名字未声明；链接错误说明声明有了但缺少实现，例如漏编译某个 .c；运行错误或逻辑错误发生在启动之后。先解决第一条编译诊断，再重编译，避免同时追踪由它引起的许多连锁消息。保留 -Wall -Wextra -Wpedantic，警告也要解释和处理。

做一个最小复现

记录完整编译命令、最小输入、预期输出与实际输出。例如总和差一项，列出 i、sum 在每轮前后的值。临时 printf 可以观察状态，但要移除或写到 stderr，避免污染正常输出。不要一次改循环条件、初值和更新，改一项后验证假设。

用断言保留发现

assert 来自 assert.h；条件为假时终止程序，适合检查程序员承诺的内部条件和测试期望。它可能被 NDEBUG 关闭，所以不能代替用户输入验证，也不能把必须发生的赋值或函数调用藏在 assert 内。外部错误用普通 if 返回状态；内部测试先执行动作，再 assert 结果。

定义与条件

可复现问题至少包含相同代码、构建方式、输入、预期与实际结果；测试是针对明确断言的可重复检查。

  • 不在 assert 中放必须执行的副作用。
  • 测试包含边界和正常情况。
  • 通过有限测试不能证明所有输入正确。

过程解释

  1. 固定一个最小输入并手算正确答案。
  2. 从诊断或状态表找到最早与预期不一致的位置。
  3. 只修改根因，重跑原用例与边界，把它保存为回归测试。

SECTION 4.1

数组：下标、长度与边界

数组把同类型的多项数据连续存放，让程序可以按下标逐项处理。

怎么理解？

像一排编号从零开始的抽屉：五个抽屉的标签是 0 到 4，标签 5 已在这一排之外。

学习目标

  • 创建与初始化
  • 长度不是终止标记
  • 传给函数时另传长度

创建与初始化

int scores[3] = {70, 80, 90}; 创建三个 int 元素。scores[0] 是第一项，scores[2] 是最后一项。int a[5] = {0}; 把所有元素初始化为零；只提供部分初始化值时，其余也被零初始化。数组不能在创建后直接用 a = b 整体赋值，要逐项复制或用明确的库操作。

长度不是终止标记

在数组本体所在作用域，可用 sizeof a / sizeof a[0] 得元素个数，结果为 size_t。循环写 i < count。C 不在普通下标访问时自动检查越界；越界不是“可能得到随机值的合法读取”，而是程序错误。二维固定数组可视为每行又是数组，a[row][col] 每一维都要合法。

传给函数时另传长度

函数形参写 const int values[] 时，会调整为指针类型，不再携带完整数组大小。函数内 sizeof values 不能求原数组长度。让接口显式接收 size_t count，并约定至少有 count 个可读元素；若 count 为零，就不访问任何元素。最大值等操作还必须专门定义空数组的行为。

定义与条件

长度为 n 的数组由 n 个连续同类型元素组成，有效下标为 0 到 n-1。数组形参调整为指针，长度需另传。

  • 每次访问都在实际数组范围内。
  • sizeof 求长度只用于真正的数组表达式，不用于已调整的形参。
  • 求平均或最大值时先规定空数据行为。

过程解释

  1. 列出元素个数与最后一个合法下标。
  2. 用 size_t 遍历并检查 i<count。
  3. 把长度随数组交给函数，不在函数里猜。

概念检查

  • C. 由内容决定

答案：B

  • A：5 已经越界。
  • B：正确，从 0 到 4 共五项。
  • C：容量由数组定义决定。

查找、排序与算法理由

同一批数据可以被查找和排序；写出循环为什么正确，比只背代码更可靠。

怎么理解？

查找像从左到右翻卡片，排序像把每张新卡插进已经排好的部分。先保证小部分有序，再逐步扩展。

学习目标

  • 线性查找
  • 插入排序
  • 代价与边界

线性查找

依次比较每个元素，找到就返回位置。未找到可返回长度 n，作为不可能的合法下标；调用者必须先检查 result < n，再访问。这个约定也能覆盖空数组。本节用小数组，逐个比较足够直观，最多检查 n 次。

插入排序

从第二项开始，临时保存当前值 key。左侧已排好序，把比 key 大的项逐个右移，最后把 key 放到空位。移动时先判断 j>0 再访问 a[j-1]，防止无符号下溢。循环不变量是：开始处理 i 时，前 i 项已按升序排列，并且仍是原来的那些值。

代价与边界

线性查找最坏比较次数随 n 线性增加；插入排序逆序输入时移动次数约按平方增加。用大 O 描述增长级别，不是某次运行的秒数。排序改变数组顺序，可能破坏与其他数组的对应关系；若数据有多个字段，后面用结构体把它们一起移动。

定义与条件

算法是解决问题的有限、明确步骤。正确性理由应说明初始化、每轮保持的性质及结束后如何得到目标。

  • 查找返回 n 时不能当作下标。
  • 排序前确认目标数组可修改。
  • 本节插入排序适用于固定长度、小规模、可比较整数数组。

过程解释

  1. 先为零项、一项和未找到情况规定结果。
  2. 用不变量解释每轮为何保持已有正确部分。
  3. 用原始数据多重集与有序性双重检查排序结果。

字符数组与字符串

C 字符串在字符数组中用零字符标明结束；容量和可见长度必须分别计算。

怎么理解？

一串字符后面有一张“到此为止”的小卡片 \0。数组容量包含卡片占的位置，屏幕不会把这张卡片当作可见文字。

学习目标

三个容易混的符号

'A' 是字符常量，"A" 是含 A 与终止零的字符串字面量，'\0' 是值为零的字符。char name[] = "Lin" 推导出四个 char 的数组：L、i、n、终止零。字符 '0' 则是数字符号的编码，不是终止零。字符串字面量本身不可修改，需要改文字时用可写字符数组。

长度和容量

strlen 来自 string.h，计算终止零之前的字符数量，不计终止零。sizeof 数组得到整个容量。strlen 要求存在可访问的终止零；对未终止数组调用可能越界。中文 UTF-8 通常一个汉字占多个字节，strlen 不等于人眼看到的字数；本书字符串算法只处理 ASCII，避免把字节反转误教成中文反转。

比较与复制

字符串内容比较用 strcmp，结果小于、等于、大于零分别表示字典序关系；不能假定结果一定是 -1 或 1。== 比较指针地址，不比较内容。复制前先确认目标容量足够包含终止零；不要把 strncpy 当成总会终止的“安全 strcpy”。本书优先在已知容量内逐项处理或用明确检查过长度的写入。

定义与条件

C 字符串是以第一个零字符终止的字符序列；承载它的数组容量至少为内容字节数加一。

  • 不修改字符串字面量。
  • 本节长度单位为 char，不声称能统计 Unicode 字符数。

过程解释

  1. 先写出包含终止零的实际数组。

SECTION 4.4

fgets：完整地接收一行

fgets 为输入设置容量上限，并保留换行信息，让程序能识别一行是否读完整。

怎么理解？

把一行水倒进有容量的杯子：杯子满了，不等于整壶水都已倒完。必须检查行尾，不能把截断的半行当成完整姓名。

学习目标

  • 理解函数参数
  • 完整与截断
  • 别混用输入方式

理解函数参数

char line[32]; fgets(line, sizeof line, stdin) 最多读取 31 个字符，然后补终止零。它读到换行会把换行也保存在数组里。成功返回 line，首次未读到字符就遇到文件结束或发生读错误时返回 NULL。本节容量是小常量，可安全作为 fgets 的 int 参数；任意巨大 size_t 不能盲目转换。

完整与截断

用 strchr(line, '\n') 查换行：找到则这次读到了行尾；没找到则可能是长行的一部分，也可能是文件最后一行没有换行。程序必须选定策略。本节交互练习要求每行以换行结束，缺换行一律拒绝；6.3 的文件读取会处理最后一行的合法无换行情形。长行要把剩余部分丢弃到换行或 EOF，才能正确读下一行。

别混用输入方式

scanf 读数字后通常留下换行，紧接的 fgets 可能读到只含换行的空行。不要靠 fflush(stdin) 清输入，ISO C 没有为这种用法定义可依赖行为。主线从这里开始统一整行读取，下一章再用 strtol 解析数字。读取字符的 getchar 返回 int，先比较 EOF，再转 char，避免丢失文件结束标志。

定义与条件

fgets 在容量允许范围内读取至换行、容量限制或输入结束，成功时补零，但不保证每次返回完整一行。

  • 数组容量至少为 2；本书本节使用 32。
  • 本节输入是无内嵌零的文本，以换行结束。
  • 读取失败后不使用缓冲区的内容。

过程解释

  1. 调用 fgets 并判断是否成功。
  2. 查找换行，按既定策略接受、拒绝或继续读取。
  3. 确认完整后才删除换行并处理内容；截断时处理残余输入。

SECTION 5.1

指针：对象、地址与解引用

指针保存对象的位置，让函数和数据结构能够间接访问对象。

怎么理解？

对象像房间，地址像门牌，指针变量像写着门牌的纸条。复制纸条不会复制房间；修改纸条也不会搬动房间。真实指针还有类型和合法访问条件，不能只把它当一个可随意计算的整数。

学习目标

  • 先画三个不同东西
  • 通过地址修改对象
  • 空指针不是空对象

先画三个不同东西

int value = 5; 创建整数对象。int *p = &value; 创建指针对象，保存 value 的地址。& 取地址，*p 在表达式中表示访问 p 指向的 int。声明里的 * 表示 p 的类型是指针，表达式里的 * 是解引用，含义依语法位置区分。

通过地址修改对象

*p = 8; 更新的是 value，不是 p。p = &other; 更新的是指针，让它转向另一个活着的 int。打印指针用 printf("%p", (void *)p)，格式结果依实现而变，不写死具体地址，也不保证相邻打印值的视觉模式。

空指针不是空对象

NULL 表示空指针常量的常见写法，可初始化尚不指向对象的指针。不能解引用 NULL，也不能解引用未初始化指针或悬空指针。检查 p != NULL 只排除了空，不能证明它一定指向活着、类型合适、可访问的对象。指针安全来自对象关系与生命周期约定。

定义与条件

类型为 T * 的指针可指向适当的 T 对象；当指向对象仍在生命周期内且访问合法时，*p 表示该对象。

  • 先初始化指针。
  • 解引用前指向正确类型、可访问且仍存活的对象。
  • 打印地址只作观察，不用于固定输出测试。

过程解释

  1. 先建立一个确定存活的对象。
  2. 用 & 取得地址并存入匹配类型的指针。
  3. 区分修改指针本身与修改 *p，并追踪对象的最终值。

SECTION 5.2

指针参数与明确的输出结果

把对象地址交给函数，可以让函数明确地修改调用者数据，或返回多个结果。

怎么理解？

普通参数像复印数据，指针参数像复印门牌：函数拿到门牌副本，仍能找到原对象。

学习目标

  • 交换两个整数
  • 状态与业务值分开
  • 调用者也承担条件

交换两个整数

void swap(int *a, int *b) 接收两个有效整数地址。先保存 *a，再把 *b 写入 *a，最后把临时值写入 *b。没有临时变量直接连续赋值会丢掉原值。传参时写 swap(&x, &y)，不是 swap(x, y)。

状态与业务值分开

一个函数既可能失败又要返回数值时，可返回成功标志，把业务值写到输出参数。例如 checked_add 返回 1 才写 *out，失败返回 0 且保持原输出不变。这样不把合法零和失败混淆。输出参数必须指向可写对象；函数要声明是否允许 NULL、是否允许输入输出指向同一对象。

调用者也承担条件

函数检查 NULL 不代表能验证任意地址是否可写。调用者负责传有效对象。对业务错误用普通分支报告，别只用 assert。接口越清楚，越能独立测试成功路径、失败路径和“不改变原输出”的承诺。

定义与条件

指针实参仍按值传递；通过该副本解引用可访问调用者对象。输出参数在成功时写入结果。

  • swap 接收两个有效可写 int 地址，可为同一对象。
  • 本节加法例限制两个输入在 0 到 100，保证和可表示。
  • 失败时输出参数保持不变，调用者先检查返回状态。

过程解释

  1. 写清输入对象和输出对象的职责。
  2. 先验证参数及可检查的范围，再写输出。
  3. 调用时传地址，成功后才使用结果。

  • B：正确，函数拿到对象地址。
  • C：大小不标识对象位置。

SECTION 5.3

数组与指针、const 与范围

理解数组何时转换为指针，可以写出同时表达位置、长度和只读意图的接口。

怎么理解？

数组是一排实际抽屉，指针是指向其中一个抽屉的标签。标签知道起点，却不自动记录整排有多少个。

学习目标

  • 转换不是同一类型
  • 尾后指针的限制
  • 只读参数与可改指针

转换不是同一类型

多数表达式中，数组名转换成指向首元素的指针；sizeof 数组、对数组取地址等场景例外。int a[3] 的 a+1 指向下一元素，按元素大小前进，不是随意增加一个字节。a[i] 对合法范围等价于 *(a+i)。数组与指针有关联，但不是同一类对象。

尾后指针的限制

可以形成指向数组最后一项之后的尾后指针，用来判断遍历结束，但不能解引用。指针加减应保持在同一数组对象内或其尾后位置；不能越界形成任意指针再“走回来”。不同对象的指针大小比较、相减也没有一般的可移植意义。

只读参数与可改指针

const int *p 表示不能经 p 修改目标 int，但 p 自身可改为指向别处。int *const p 表示指针对象不能改指向，但可通过它改目标。const 不延长生命周期。数组只读计算接口优先用 const int *values, size_t count，让调用者明确提供范围。

定义与条件

数组到指针转换产生首元素地址；指针算术以目标元素为单位，并受同一数组及尾后边界限制。

  • 函数接收至少 count 项的有效数组；count 为零时不访问。
  • 不解引用尾后指针。
  • 不将任意两个独立对象地址做大小比较或相减。

过程解释

  1. 识别当前表达式里的数组是否发生转换。
  2. 把指针位置与实际数组长度一起追踪。
  3. 用 const 限制不必要的写入，迭代始终在合法范围。

概念检查

const int *p 中 const 限制什么？

  • B. 修改 p 的指向
  • C. 任何人修改原对象

答案：A

  • A：正确，只限制通过这个访问路径的写入。
  • B：p 本身可在合法范围改指向。
  • C：其他有权写入的访问路径未必受限制。

SECTION 5.4

生命周期、malloc 与 free

动态内存让程序在运行时申请空间；每块空间必须有明确的拥有者和释放时机。

怎么理解？

借来的柜子要登记谁负责归还。把柜子地址再抄一份，并不会多出一个柜子，也不会多出一次归还权。

学习目标

  • 局部地址不能带出函数
  • 申请成功后才能访问
  • 一次释放与别名

局部地址不能带出函数

int *bad(void) { int x=1; return &x; } 返回后 x 已结束生命周期，地址变成悬空。即使某次似乎读到 1，也不能据此认定合法。需要返回数值就按值返回，需要持续对象则由调用者提供空间或明确分配动态空间。

申请成功后才能访问

malloc 来自 stdlib.h，接收字节数，失败返回 NULL，成功所得空间初始内容不确定。申请 n 项先检查 n <= SIZE_MAX / sizeof *p，避免乘法回绕。本节固定申请三项，不需要巨大长度，但仍说明一般边界。C 中不必强转 malloc 返回值；包含正确头文件，使用 sizeof *p 避免类型名重复。

一次释放与别名

free 释放一块仍由本程序拥有的动态分配空间；free(NULL) 允许。不能释放局部数组、指向分配块中间的地址，也不能释放同一块两次。free 后别名也失效；把拥有者设 NULL 可减少自身误用，但不会自动清除其他副本。所有权交接与错误路径都必须写清。

定义与条件

malloc 分配适当对齐的动态存储，free 结束该分配的可用生命周期；之后不得通过旧指针访问或再次释放该块。

  • 分配尺寸计算不溢出；本书避免零大小分配。
  • 每次分配结果先检查，再初始化读取。
  • 每块成功分配最终恰好由一个拥有者释放一次。

过程解释

  1. 确定容量、检查尺寸并申请。
  2. 检查非 NULL，初始化所有将读取的元素。
  3. 最后一次使用后释放；失败路径也释放之前已拥有的资源。

概念检查

  • A. 继续写第零项
  • B. 处理失败，不解引用
  • C. 调用两次 free

答案：B

  • A：NULL 不指向分配好的元素。
  • B：正确，报告失败或清理后返回。
  • C：free(NULL) 允许但不能代替错误处理。

动态数组与 realloc 的失败路径

当记录数量运行时才知道，可以用“数据指针、长度、容量”组成可增长数组。

怎么理解？

长度是已入住人数，容量是总房间数。扩建失败时，原楼还在，不能先丢掉原楼地址。

学习目标

  • 先建立不变量
  • realloc 必须用临时指针
  • 增长前检查上限

先建立不变量

动态表使用 data、size、capacity。始终满足 size<=capacity，只有下标小于 size 的元素已初始化并属于数据；capacity-size 部分只代表备用空间。初始 data=NULL、size=0、capacity=0，销毁后恢复这三项。容量不等于元素数，不能把备用空间拿去统计。

realloc 必须用临时指针

realloc(old, bytes) 成功时返回新块，可能移动；原指针和所有旧元素地址都不可再用。失败返回 NULL，原分配仍归你所有。因此写 tmp=realloc(data,bytes)，成功后再 data=tmp。直接 data=realloc(...) 在失败时丢失原指针，造成泄漏。避免零大小请求的复杂边界。

增长前检查上限

翻倍容量前检查乘法和业务上限。入门项目最多接收 100 条，容量增长到 100 就停止，这也限制了总分与内存需求。插入操作先确认空间成功，再写元素、最后增加 size；失败保持原记录表不变。不要在扩容后继续使用之前保存的元素指针。

定义与条件

可增长数组以拥有者结构管理分配块；realloc 失败保留原分配，成功后必须采用新指针并废弃旧别名。

  • 尺寸计算不溢出，容量不超过项目上限。
  • 传给 realloc 的地址为当前仍拥有的分配块首地址或 NULL。
  • 本节微型示例只演示固定增长，完整通用逻辑在项目中。

过程解释

  1. 确认需要的长度是否超过容量。
  2. 计算并检查新容量，用临时指针申请增长。
  3. 成功后更新指针与容量，写入新项，最后更新长度。

文本文件、错误检查与关闭

文件让数据在程序退出后仍能保存；读写必须同时考虑打开失败、处理中失败和关闭失败。

怎么理解？

打开文件像借一本册子，读取位置会前进，最后必须归还。打开成功只说明拿到了册子，不保证之后每一页都能读写成功。

学习目标

  • 文件指针与模式

文件指针与模式

FILE *fp=fopen("notes.txt","r") 尝试只读打开相对路径，失败返回 NULL；"w" 创建或截断文件，旧内容会被清空；"a" 追加。相对路径从程序当前工作目录解释，不从源文件所在目录解释。不要在未确认路径时对重要文件使用 w。

循环不能预判 EOF

while(fgets(buf,sizeof buf,fp)!=NULL) 是常见逐段读取方式。while(!feof(fp)) 不对：文件结束标志通常在一次读取尝试遇到结束之后才设置，预判会多处理一次旧缓冲。读取循环结束后用 ferror(fp) 区分读取错误与正常结束。文件最后一行可以没有换行，解析器应写清是否接受。

写入和关闭也会失败

fprintf 返回负数表示失败；fclose 成功返回零，失败返回 EOF。缓冲写入的错误可能延迟到关闭时出现。每条退出路径都要关闭已经打开的文件，但关闭后不能再次使用 FILE 指针。本书项目先验证整份输入才输出报告，不给坏数据生成看似完整的部分统计；这不等于支持操作系统断电下的原子存储。

定义与条件

标准 I/O 流以 FILE * 表示；读取返回值决定是否获得数据，ferror 区分错误，fclose 结束流并报告关闭结果。

  • 只有 fopen 成功后使用流。
  • 写模式可能截断旧文件。
  • 读取循环中的缓冲区只在读取成功时使用。

过程解释

  1. 打开并立即检查。
  2. 每次读写检查返回值，读完检查 ferror。
  3. 关闭一次并检查关闭结果，保留前面已发生的错误。

  • B. 进入循环前的 feof

SECTION 6.4

用 strtol 验证整数文本

把整行文本转换为数字时，要分别检查“读到了数字”“有没有多余字符”“是否超范围”。

怎么理解？

三道关卡分别查格式、机器范围、业务范围；只过一道不能说明数据可用。

学习目标

  • 先读文本，再转换
  • 三个失败条件
  • atoi 不承担验证

先读文本，再转换

strtol 来自 stdlib.h，按给定进制转换开头的数字，返回 long，并通过 end 指针告诉你停在哪里。调用前 errno=0，之后检查 errno==ERANGE。它会跳过前导空白，也可接受正负号；接口默认行为不一定等于你的业务规则，要额外规定并检查。

三个失败条件

end==text 表示没有转换任何数字。*end 不为终止零，说明仍有未接受的后缀；若允许换行或空白，先明确定义并消耗它们。errno==ERANGE 代表结果超出 long 可表示范围。通过这些检查后，还要比较 INT_MIN/INT_MAX 或 0..100 这样的目标范围，最后才强转为 int。

atoi 不承担验证

atoi 没有 end 参数，难区分合法零和无效输入，也不能像这里一样可靠处理越界诊断。本节解析函数先限制完整文本为一个整数表示，允许 strtol 本身接受的前导空白和符号，拒绝任何后缀。项目的“姓名 空格 分数”有更窄格式，会明确用专门规则检查，不能宣称一个函数适用所有输入协议。

定义与条件

strtol 使用 endptr 报告未转换后缀，并通过 errno 的 ERANGE 报告范围错误；调用者负责完整格式和目标范围验证。

  • 输入为有终止零的文本。
  • 调用前清零 errno。
  • 只在全部验证通过后写输出参数或转换为窄类型。

过程解释

  1. 清 errno，调用 strtol 并保存 end。
  2. 检查无数字、ERANGE、后缀和业务范围。
  3. 全部通过才转换成 int 并更新输出，否则保持原状态。

概念检查

"12x" 只允许纯整数时，应该？

  • B. 检查 *end 后拒绝
  • C. 把 x 自动删除

答案：B

  • A：前缀可转换不等于整条格式合法。

  • C：静默删改输入会掩盖错误。

SECTION 7.1

头文件、多文件与构建

把声明与实现分开，可以让一个项目的多个源文件共享接口，同时各自保持清楚的职责。

怎么理解？

头文件像菜单，源文件像厨房。看见菜单知道能点什么，但链接时仍必须找到真正做菜的实现。

学习目标

  • 一个声明，一份定义
  • 头文件保护
  • 编译与链接分开理解

一个声明，一份定义

在 stats.h 放 int max_score(int a,int b); 原型，在 stats.c 放实现，main.c 包含头文件并调用。声明可在不同编译单元出现，普通外部函数定义通常只保留一份。不要在头文件里直接放普通全局对象定义，否则多个 .c 包含时容易出现重复定义。

头文件保护

使用 #ifndef STATS_H、#define STATS_H 和 #endif 包住头文件正文，防止同一翻译单元重复包含造成类型重复定义。自有头文件写双引号，标准头文件写尖括号。头文件应包含自己声明所需的类型头文件，不要求调用者碰巧先包含某个文件。文件内辅助函数可用 static 限制链接可见性。

编译与链接分开理解

gcc -std=c17 -Wall -Wextra -Wpedantic main.c stats.c -o app 会编译两份源文件再链接。漏掉 stats.c 时，即使原型正确，也会缺少函数实现。头文件不是需要单独链接的实现文件。较大项目可用 -c 先得到目标文件，再链接；本书项目给出一条直接可用的命令，避免先被构建系统打断。

定义与条件

头文件提供可共享声明；各 .c 独立翻译，链接器把它们的定义与引用连接。

  • 共享声明保持一致。
  • 源文件实现包含自己的接口头文件以暴露类型不一致。
  • 命令必须列出所有参与链接的实现源文件。

过程解释

  1. 把公开类型和函数原型放进带保护的头文件。
  2. 把实现放进 .c，main 只调用公开接口。
  3. 一次编译链接全部实现文件，用缺失和重复定义诊断检查职责。

  • B. 声明共享类型与函数接口
  • C. 自动安装编译器

答案：B

  • A：运行数据应存明确数据文件。
  • B：正确，实现通常在 .c。
  • C：编译器安装与头文件职责不同。

SECTION 7.2

递归与调用栈的边界

递归让函数用更小的同类问题求解当前问题；每次调用都必须走向明确的终点。

怎么理解？

把任务交给处理更小任务的自己，直到最小任务直接回答。每次交接都保留一张等待返回的便条，太深就会耗尽存储。

学习目标

  • 基例与缩小
  • 每层有自己的局部对象
  • 优先选可解释方案

基例与缩小

阶乘可写为 n 为 0 时返回 1，否则 n*factorial(n-1)。基例阻止继续调用，递归步骤严格缩小非负 n。输入负数不会自然走到零，所以必须在入口限制。unsigned long long 也有上限，本节仅允许 0 到 10，结果 3628800 在其标准保证范围内。

每层有自己的局部对象

factorial(3) 等待 factorial(2)，后者等待 factorial(1)，再到 factorial(0)。返回顺序与调用深入顺序相反。每层参数是独立副本。不能把局部地址返回给上层继续使用；生命周期规则没有因为递归而改变。

优先选可解释方案

简单求和与阶乘可用循环，避免深层调用。递归适合本身有树形或分治结构的问题，但需要分析深度和重复计算。C 不保证尾调用优化，也没有固定可移植的最大递归层数。不要拿无限递归测试机器“最大安全深度”当作可靠程序设计。

定义与条件

递归函数直接或间接调用自身；正确终止依赖基例，以及每次调用使一个有下界的度量严格减小。

  • 本节阶乘仅接收 0..10。
  • 整数结果与中间乘积可表示。
  • 调用深度受控，不依赖尾调用优化。

过程解释

  1. 先给最小输入写直接答案。
  2. 证明每次递归参数向基例靠近。
  3. 从最深基例向外回填结果，检查每层乘积与深度。

概念检查

  • B. 只要调用自己
  • C. 只要返回值不是 void

答案：A

  • A：正确，输入也必须在约定范围内。
  • B：自调用本身没有终止保证。
  • C：返回类型不决定终止。

SECTION 7.3

无符号位运算与标志

位运算可以把多个独立开关放进一个整数；要先区分逻辑判断与逐位操作。

怎么理解？

把低位看成几个独立灯，掩码像只看某盏灯的挡板。这个模型只解释无符号整数值的位，不依赖内存的字节顺序。

学习目标

  • 四个常见运算
  • 设置、检查、清除
  • 移位的严格边界

四个常见运算

& 按位与、| 按位或、^ 按位异或、~ 按位取反。它们与 &&、||、! 的逻辑语义不同。逻辑运算只关心是否为零，并可能短路；位运算对位计算且没有这样的短路规则。使用 unsigned int 和带 U 后缀的常量，减少有符号表示与提升带来的干扰。

设置、检查、清除

定义 READ=1U、WRITE=2U，flags|=WRITE 设置写标志，(flags&WRITE)!=0 检查，flags&=~WRITE 清除。~ 会翻转类型的所有值位，不只是屏幕上写出的几位，因此清除时要和原 flags 相与。输出无符号十进制使用 %u。

移位的严格边界

1U<<k 表示把一个位向左移 k 位，要求 k 非负且小于提升后左操作数类型的位宽。右移无符号数按数值除以相应的 2 的幂截断。不要对负有符号数照搬无符号规则。为可移植性，本节只用低 0..3 位，标准保证 unsigned int 至少足以容纳它们。

定义与条件

位运算按整数表示的位计算；移位次数必须在合法位宽范围内，本书只讨论无符号值。

  • 只操作 unsigned int 与匹配的 U 常量。
  • 移位次数使用已证明小于类型位宽的常量。
  • 不把位值模型冒充实际内存地址或字节序。

过程解释

  1. 给每个开关分配不重叠的掩码。
  2. 分别用或设置、与检查、与取反掩码清除。
  3. 每步用小十进制值独立核对，不混用逻辑操作符。

概念检查

设置标志 WRITE 而保留其他位应写？

  • A. flags |= WRITE
  • B. flags = WRITE
  • C. flags && WRITE

答案：A

  • A：正确，按位或保留已有位。
  • B：赋值会丢掉其他标志。
  • C：逻辑表达式不执行设置动作。

边界测试与运行时检查工具

把契约变成测试矩阵，并结合编译器工具，可以更早发现越界、溢出和状态损坏。

怎么理解？

一张检查表覆盖正常、边界与失败，比“随便输入几次没崩”更能说明你检查了什么。工具像报警器，没报警不代表所有问题都不存在。

学习目标

  • 测试矩阵
  • 动态检查的用法
  • 失败路径需要专门证据

测试矩阵

对分数解析列出 0、100、-1、101、空串、后缀、超长数字；对容器列出空表、一项、重复姓名、容量上限、再加一项；对文件列出不存在、空文件、CRLF、末行无换行、过长行。每项有明确预期，不把“能运行”当标准。项目章给出实际用例而不是仅列名词。

动态检查的用法

支持这些工具的 Clang/GCC 环境可在编译和链接时加 -g -O1 -fsanitize=address,undefined -fno-omit-frame-pointer。AddressSanitizer 可发现执行路径上的许多越界和释放后使用；UndefinedBehaviorSanitizer 可发现部分未定义行为。Windows 工具链支持可能不同，先用普通构建，按工具官方说明另跑。不要为了让书能用而要求初学者先配置全部工具。

失败路径需要专门证据

普通小数据几乎不会自然触发 malloc 失败，所以不能把跑完成功路径写成“内存失败都测过了”。可通过替代分配器进行故障注入，或明确记录尚未执行的路径。本书项目自动检查格式与容量失败、失败不改状态；实际系统分配失败和 I/O 设备故障不声称已穷尽模拟。

定义与条件

测试用例由输入、环境条件、操作和可核对的预期组成；运行时检查只覆盖实际执行到的行为与工具支持的错误类别。

  • 先有独立预期再运行。
  • 不运行故意带未定义行为的片段来规定“正确输出”。
  • 工具通过不等于全输入证明。

过程解释

  1. 从接口每条约束推导正常、边界、拒绝用例。
  2. 对比状态与输出，不仅检查退出码。
  3. 运行普通构建与支持的 sanitizer 构建，记录真实覆盖和局限。

  • B. 具体用例、环境、结果与未覆盖部分

综合项目二：记录表、所有权与排序

怎么理解？

公开接口

综合项目三：整份加载与文本协议

文件模块先把输入放入临时表，只有整份合法才替换旧表，避免失败留下半成品。

怎么理解？

像批次验货：全部合格才入库，任何一件失败则退回这一批，原仓库不动。

学习目标

  • 有界逐字符读行
  • 严格解析两字段
  • 提交与回滚

有界逐字符读行

项目 read_line 用 fgetc 的 int 结果逐个读取，最多保存 63 个字符加零。这样可以明确拒绝内嵌零和超长行，接受末行无换行，并在读到 LF 后去掉可选的 CR。裸 CR 仍被格式检查拒绝。返回值区分正常行、正常结束、读取错误、超长或非法字节；不把截断行交给解析器。

严格解析两字段

parse_student 先找唯一空格，前面必须 1..20 个英文字母；后面至少一个十进制数字且只有数字，先拒绝符号与空白，再用 strtol 和 errno 检查值与范围。输出 Student 只在成功时写入。空行、尾部空格、重复分隔符都拒绝，不悄悄纠正协议。

提交与回滚

gb_load 要求目标表已初始化。先打开文件并建立 staging 临时表，逐行解析并 gb_add。任何一步失败都关闭文件、销毁 staging，原目标保持原样；完全成功且关闭无误后，销毁旧目标并把 staging 所有权交给目标。结构体赋值在这里是有意的所有权转移，转移后的 staging 不再销毁同一块。

定义与条件

事务式加载在所有可检查步骤成功后一次转移结果；失败时销毁临时状态并保留原目标。

  • 目标表先初始化。
  • 输入遵守本项目 ASCII 两字段协议。
  • 加载成功转移所有权，失败清理临时表；不承诺文件系统的原子写入。

过程解释

  1. 逐行读取并拒绝截断与非法字节。
  2. 在临时表中解析、查重、追加，错误即清理。
  3. 检查读取与关闭结果，成功后才替换目标。
